# 07. 현장 리서치 — 스톱워치의 고충과 설계 반영

수영 코치·부모가 스톱워치로 여러 명을 잴 때 겪는 실제 고충을 공개 자료(앱스토어 리뷰, 코칭 가이드, 커뮤니티)에서 조사하고, 본 앱이 각 문제를 어떻게 푸는지 매핑했다.

## 조사한 고충 ↔ 설계 반영

| # | 현장 고충 (출처) | 본 앱의 반영 |
| --- | --- | --- |
| 1 | **일반 스톱워치는 표시줄이 한 줄** — 여러 선수의 스플릿을 동시에 보관·회상하기 어렵다. 3명 이상이면 스크롤하다 누가 누군지 놓친다. | 레인별 행이 **항상 동시에 보임**. 일반 인원(≤5)에서 **세로 스크롤 없음**. 색+번호+진행 도트로 즉시 구분. |
| 2 | **가까이 들어오면 어느 스플릿이 누구 건지 기억 못 함.** | **포착과 배정을 분리**: 단일 버튼으로 시간만 먼저 찍고(리듬), 누구인지는 **레인을 직접 탭**하거나 **측정 후 배정**한다. (선두 앱들의 "스플릿을 나중에 레인으로 배정" 방식.) |
| 3 | **눈은 물(스트로크·턴)에 둬야** 하는데 화면을 보게 된다. | **다음 도착 레인 예측**을 크게 강조 → 맞으면 화면 안 보고 LAP만. 큰 탭 타깃. (로드맵: **볼륨 버튼** 조작으로 완전 eyes-free — 일부 앱이 채택.) |
| 4 | 측정한 숫자를 **노트/엑셀로 옮기는 수기 작업**이 번거롭고 누락·오기 잦다. | 마지막 Stop → **기록지에 자동 저장**. 수기 0. |
| 5 | 이전 기록·베스트와 **비교(향상)** 가 어렵다. | 배정 화면에서 **이전→오늘 향상치·PB 즉시** 표시. |
| 6 | **실수로 정지/리셋** 눌러 측정 날림. | 리셋을 주동선에서 분리(빨강·하단). (로드맵: 리셋 **길게 눌러 확인**.) |
| 7 | 전용 스톱워치는 비싸고(예: FINIS 3X300) **스플릿 300개 저장**으로 수기 부담만 던다. | 폰 하나로 **무제한 저장 + 자동 정리 + 추천/향상**까지. |

## 핵심 설계 결론

> **"알고리즘만으로 레인 순서 역전을 100% 풀 수는 없다"** ([03 §3.3], 벤치마크). 그래서 **UI로 푼다.**
>
> - **단일 LAP 버튼** = 예측된 다음 레인에 기록(리듬, 시선 최소). 잘 맞는 일반 상황용.
> - **레인 행 직접 탭** = 방금 벽 찍은 레인을 코치가 직접 지정(WYSIWYG). **순서 역전·초접전에서도 100% 정확** — 코치는 누가 들어왔는지 *보고 있기* 때문.
> - 둘 다 같은 "한 동작" 수준(큰 타깃)이라, 선수별 작은 버튼의 오탭 문제는 없다.
> - **볼륨 버튼·하드웨어 키로 LAP**(eyes-free): 시선을 물에 두고 기록(FR-T3c).
> - 그래도 틀리면 **측정 후 배정 화면**에서 드롭다운/맞바꾸기로 최종 보정.

직접 탭이 순서 역전(갈때 2-3-4-5 / 올때 2-4-3-5)을 실측 100%로 해결함을 데모로 검증했다([03 §3.4]).
