# 02. 요구사항 (Requirements)

표기: **FR** = 기능 요구사항, **NFR** = 비기능 요구사항. 우선순위 `P0`(MVP 필수) · `P1`(MVP 권장) · `P2`(추후).

---

## 2.1 기능 요구사항 — 세션 설정 (Setup)

| ID | 우선 | 요구사항 | 비고 / 인수 조건 |
| --- | --- | --- | --- |
| FR-S1 | P0 | 코스/구간 단위를 **25m, 25y, 50m** 중 선택할 수 있다. | 구간 단위 = 스플릿 1개의 거리. |
| FR-S2 | P0 | 종목(자유형/배영/평영/접영/혼영)과 총 거리(예: 100y)를 선택한다. | `세그먼트 수 = 총거리 / 구간단위` (정수여야 함, 아니면 경고). |
| FR-S3 | P0 | 한 세션(heat)에 **레인 1~N**을 두고 각 레인에 선수를 배정한다. | N 기본 1~8. 레인=position. |
| FR-S4 | P0 | 각 레인의 선수를 **기존 기록 기반으로 추천**한다. | 추천 근거: 최근 함께 측정한 조합, 최근 활동, 동일 세트. [03 §3.6] |
| FR-S5 | P0 | 레인별로 종목/거리를 **다르게** 설정할 수 있다(개별 오버라이드). | 기본은 세션 공통값 상속. |
| FR-S6 | P0 | 레인의 선수를 변경하면 **타이머가 리셋**된다. | 측정 시작 후 변경 시 확인 다이얼로그 → 리셋. [핵심 요구] |
| FR-S7 | P1 | 자주 쓰는 세트를 **프리셋**으로 저장/불러오기. | 예: "100 free × 25y, 레인 1-3". |

## 2.2 기능 요구사항 — 측정 (Timing, 핵심)

| ID | 우선 | 요구사항 | 비고 / 인수 조건 |
| --- | --- | --- | --- |
| FR-T1 | P0 | **단일 Start 버튼**으로 모든 레인이 동시에 출발한다. | t0 1회 캡처. |
| FR-T2 | P0 | 측정 중 **전체 경과 시간(러닝 클락)**을 항상 크게 표시한다. | 10ms 단위 갱신 권장. |
| FR-T3 | P0 | **단일 Lap 버튼** 하나만 존재한다(선수별 Lap 버튼 없음). | 한 번 누를 때마다 1개의 스플릿 타임스탬프 생성. |
| FR-T4 | P0 | 각 Lap 탭은 "다음에 도착할 차례인 선수"에게 **자동 배정**된다. | 배정 알고리즘 [03 §3.3]. |
| FR-T5 | P0 | 배정 결과(어느 레인/선수, 구간 스플릿, 누적)를 **즉시** 화면에 표시·하이라이트. | 색상 코딩으로 어느 레인인지 즉시 인지. |
| FR-T6 | P0 | 자동 배정이 틀리면 **마지막 Lap을 다른 레인으로 재할당**할 수 있다. | 시계 멈추지 않음. 1탭 수정. [03 §3.4] |
| FR-T7 | P0 | 한 선수가 마지막 세그먼트를 찍으면 그 탭이 그 선수의 **Stop(완주)** 으로 처리된다. | 완주한 레인은 배정 후보에서 제외. |
| FR-T8 | P0 | **모든 선수가 완주(마지막 Stop)** 하면 측정이 종료되고 저장 단계로 넘어간다. | [FR-R1] |
| FR-T9 | P0 | **Undo**: 직전 Lap 취소(잘못 누름/중복 탭). | 다단계 undo 권장(P1). |
| FR-T10 | P1 | **누락 보정**: 빠뜨린 스플릿을 수동 추가/삽입. | 측정 중 또는 종료 후. |
| FR-T11 | P1 | 측정 중 한 레인을 **DNF(미완주)** 로 종료. | 해당 레인 후보 제외, 부분 기록 저장. |
| FR-T12 | P0 | **전체 일시정지/재개** 및 **전체 리셋**. | 리셋은 확인 필요. |
| FR-T13 | P1 | Lap 탭 시 **햅틱 + (선택)사운드** 피드백, 배정 레인 색으로 진동 길이 구분 X(단순). | 누름 확인감. |

## 2.3 기능 요구사항 — 저장/기록지 (Records)

| ID | 우선 | 요구사항 | 비고 / 인수 조건 |
| --- | --- | --- | --- |
| FR-R1 | P0 | 측정 종료 시 **저장 확인 화면**을 보여주고, 확인하면 전 선수 기록을 자동 저장. | 자동 저장이되 직전 검토 가능. |
| FR-R2 | P0 | 저장되는 선수 기록: 날짜, 세트(종목/거리/코스), **세그먼트별 스플릿 + 누적**, 총 기록. | [04 데이터 모델] |
| FR-R3 | P0 | 선수별 **기록지**: 세션 목록, 각 세션의 스플릿 펼쳐보기. | 메인 화면 2개 중 하나. |
| FR-R4 | P1 | 선수별 **베스트 타임**(종목/거리별)과 **추세 그래프**. | 동기부여·코칭. |
| FR-R5 | P1 | 기록 **수정/삭제**, 메모(컨디션·세트 의도) 추가. | |
| FR-R6 | P1 | 데이터 **내보내기**(CSV) / 공유(이미지). | 학부모 공유. |
| FR-R7 | P0 | 선수 **로스터 관리**(추가/이름/소속/메모). | |

| NFR-2 (반응성) | P0 | Lap 탭 → 화면 반영 지연 < **80ms**, 입력 유실 0. | 빠른 연타(2탭/초)에도 모두 기록. |
| NFR-3 (오프라인) | P0 | 네트워크 없이 모든 핵심 기능 동작, 로컬 영속 저장. | poolside 가정. |
| NFR-4 (화면 유지) | P0 | 측정 중 **화면 꺼짐/잠금 방지**(Wake Lock). | |
| NFR-5 (가독성) | P0 | 야외 햇빛 대비. 명도 대비 ≥ WCAG AA, 타이머 숫자 대형. | [06 디자인] |
| NFR-6 (터치 타깃) | P0 | 주요 버튼 ≥ **64px**, 메인 Lap 버튼은 화면 하단 풀폭·대형. | 젖은 손/장갑. |
| NFR-7 (데이터 안전) | P0 | 앱 강제 종료/크래시 시에도 **진행 중 측정 복구**(자동 스냅샷). | |
| NFR-8 (접근성) | P1 | 스크린리더 라벨, 색맹 대비(색+숫자/패턴 병행). | 레인 구분을 색에만 의존하지 않음. |
| NFR-9 (성능) | P1 | 8레인 동시 측정 시에도 60fps 유지. | |
| NFR-10 (프라이버시) | P0 | 아동 데이터: 로컬 우선, 외부 전송은 명시적 동의. | 미성년자 보호. |

## 2.5 플랫폼 / 기술 방향 (제안, 확정 아님)

- **타깃**: 모바일 우선(폰을 poolside에서 사용). 태블릿 레이아웃 지원(P1).
- **권장 스택 후보**
  - PWA(React/Svelte) + IndexedDB + Web Wake Lock/Vibration API → HTML 프리뷰와 일관, 설치형 웹.
  - 또는 React Native / Flutter(네이티브 햅틱·백그라운드 안정성 우위).
- **결정 필요 항목**: 위 둘 중 택1, 클라우드 동기화 도입 시점, 다중 디바이스 정책.
- 본 문서의 디자인 토큰/컴포넌트는 스택 비의존으로 작성됨([06]).
