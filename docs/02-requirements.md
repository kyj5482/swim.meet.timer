# 02. 요구사항 (Requirements)

표기: **FR** = 기능 요구사항, **NFR** = 비기능 요구사항. 우선순위 `P0`(MVP 필수) · `P1`(MVP 권장) · `P2`(추후).

> ### ⭐ 핵심 흐름 (v2): "익명 측정 → 사후 배정"
> 출발 전에 선수를 배정하지 않는다. **익명 슬롯(1번·2번·…)** 으로 먼저 측정하고, **측정이 끝난 뒤** 각 슬롯에 선수를 배정한다.
> - 측정 중 슬롯은 _도착 순서_ 로 자동 정의된다(첫 length를 먼저 끝낸 사람 = 1번). 이후 구간은 각 슬롯이 *자기 페이스* 로 추적된다. [03 §3.3]
> - 배정은 **기록된 타임을 선수 이력과 대조해 추천**하고, 배정 즉시 **이전 대비 향상/PB(실력 체크)** 를 보여준다. [03 §3.6]
> - 모든 시간은 수영 규격인 **1/100초(소수점 2자리)** 로 표시한다. [NFR-1]
>
> 이 흐름은 초기안(출발 전 레인-선수 배정 + 선수 변경 시 리셋)을 사용성 검토 결과로 대체한 것이다. 변경 이력은 [§2.7].

## 2.1 기능 요구사항 — 세션 설정 (Setup)

| ID | 우선 | 요구사항 | 비고 / 인수 조건 |
| --- | --- | --- | --- |
| FR-S1 | P0 | 코스/구간 단위(**25m, 25y, 50m**)는 **앱 설정에서 한 번만** 정하고 보존된다. 측정 화면(설정·러닝)에는 **표시만** 한다. | 다니는 풀(야드/미터)은 고정이라 매번 고르지 않음. 설정 시트에서 변경. 구간 단위 = 스플릿 1개의 거리. |
| FR-S2 | P0 | 종목(자유형/배영/평영/접영/혼영)과 총 거리(예: 100y)를 선택한다. | `세그먼트 수 = 총거리 / 구간단위` (정수여야 함, 아니면 경고·출발 비활성). |
| FR-S3 | P0 | 인원 수를 **+/- 스테퍼**로 1~N(기본 3, 최대 8) 조절한다. 각 자리는 **익명 슬롯**(1번..N번). | 출발 전 선수 지정 없음. |
| FR-S4 | P0 | 슬롯별로 종목/거리를 **다르게** 설정할 수 있다(개별 오버라이드). | 기본은 세션 공통값 상속. |
| FR-S5 | P1 | 자주 쓰는 세트를 **프리셋**으로 저장/불러오기. | 예: "100 free · 25y · 3명". |
| FR-S6 | P0 | 측정 시작 후 **인원 수를 바꾸면 타이머가 리셋**된다. | 확인 다이얼로그 → 리셋. (선수 배정은 측정 후이므로 비파괴적.) |

## 2.2 기능 요구사항 — 측정 (Timing, 핵심)

| ID | 우선 | 요구사항 | 비고 / 인수 조건 |
| --- | --- | --- | --- |
| FR-T1 | P0 | **단일 Start 버튼**으로 모든 슬롯이 동시에 출발한다. | t0 1회 캡처. |
| FR-T2 | P0 | 러닝 클락을 **큰 `MM:SS` + 작은 `.SS`(1/100초)** 로, **항상 화면 안에** 표시한다. | 분리 표시로 폭 넘침 방지. 내부는 ms(centisecond 반올림). |
| FR-T3 | P0 | **단일 LAP 버튼**은 **예측된 다음 레인**에 기록한다(버튼에 `다음 ▸ N번` 표시). | 리듬·시선 최소. [03 §3.3] |
| FR-T3b | P0 | **레인 행을 직접 탭**하면 그 레인에 기록한다(WYSIWYG, 큰 풀폭 타깃). | 순서 역전·초접전에서도 코치가 본 대로 100% 정확. [03 §3.4], [07] |
| FR-T4 | P0 | LAP 예측은 **라운드 단조매칭**(length 단위로 예측 도착순 정렬·매칭)으로 레인 순서 변화에 견딘다. | 벤치마크 그리디 25% → 단조매칭 ~72%, 직접 탭 100%. [03 §3.3], [bench/RESULTS.md] |
| FR-T4b | P2 | **레인 이력 모드(선택)**: 레인↔선수 사전 지정 시 과거 구간 프로파일로 예측. | 복귀역전 50%→97%. [03 §3.3a] |
| FR-T5 | P0 | 기록 결과(어느 슬롯, 구간 스플릿, 누적)를 **즉시** 색상 코딩으로 표시·하이라이트. | 색+번호+도트 다중 인코딩. |
| FR-T6 | P0 | 오기록은 **실행취소** 또는 측정 후 배정 화면에서 보정한다. | 직접 탭이 주 보정 수단이라 측정 중 별도 재할당 UI 불필요. [03 §3.4] |
| FR-T7 | P0 | 한 슬롯이 마지막 세그먼트를 찍으면 그 탭이 그 슬롯의 **Stop(완주)** 으로 처리된다. | 완주 슬롯은 배정 후보에서 제외. |
| FR-T8 | P0 | **모든 슬롯이 완주**하면 측정이 종료되고 **선수 배정 화면**으로 넘어간다. | [FR-R1] |
| FR-T9 | P0 | **랩 진행도**(N/M)와 남은 인원을 표시한다. | 코치가 진행 상황 파악. |
| FR-T10 | P0 | **Undo**: 직전 Lap 취소(잘못 누름/중복 탭). | 다단계 undo 권장(P1). |
| FR-T11 | P1 | **누락 보정**: 빠뜨린 스플릿을 수동 추가/삽입. | 측정 중 또는 종료 후. |
| FR-T12 | P1 | 측정 중 한 슬롯을 **DNF(미완주)** 로 종료. | 해당 슬롯 후보 제외, 부분 기록 저장. |
| FR-T13 | P0 | **전체 일시정지/재개** 및 **전체 리셋**. | 리셋은 확인 필요. |
| FR-T14 | P1 | Lap 탭 시 **햅틱 + (선택)사운드** 피드백. | 누름 확인감. |

## 2.3 기능 요구사항 — 선수 배정 (Assign, 측정 직후)

| ID | 우선 | 요구사항 | 비고 / 인수 조건 |
| --- | --- | --- | --- |
| FR-A1 | P0 | 측정 종료 시 **배정 화면**에서 각 슬롯의 총기록·구간 스플릿을 보여준다. | 슬롯 색·번호 유지. |
| FR-A2 | P0 | 각 슬롯에 **기존 기록 기반 추천 선수**를 미리 채우고, 드롭다운으로 변경 가능. | 추천=기록 대조 매칭. [03 §3.6] |
| FR-A3 | P0 | 배정된 선수의 **이전 기록 → 오늘 기록 향상치**와 **PB 여부**를 즉시 표시. | "실력 향상 체크" 핵심. before→after + ▼/▲ + 🏅PB. |
| FR-A4 | P0 | 슬롯 기록이 서로 **너무 가까우면(예: <0.40초)** "확인 필요" 경고 + **원탭 맞바꾸기** 제공. | 시간만으론 구분 불가한 경우의 안전장치. [03 §3.5a] |
| FR-A5 | P0 | 상단에 **요약 헤드라인**(향상 N명 · PB N명 · 총 N명)을 보여준다. | 코치의 한눈 결과. |
| FR-A6 | P0 | **저장** 시 각 슬롯 → 해당 선수 기록지에 1건씩 트랜잭션 저장. | 전부 저장 또는 전부 롤백. |

## 2.6 플랫폼 / 기술 방향 (제안, 확정 아님)

- **타깃**: 모바일 우선(폰을 poolside에서 사용). 태블릿 레이아웃 지원(P1).
- **권장 스택 후보**
  - PWA(React/Svelte) + IndexedDB + Web Wake Lock/Vibration API → HTML 프리뷰와 일관, 설치형 웹.
  - 또는 React Native / Flutter(네이티브 햅틱·백그라운드 안정성 우위).
- **결정 필요 항목**: 위 둘 중 택1, 클라우드 동기화 도입 시점, 다중 디바이스 정책.
- 본 문서의 디자인 토큰/컴포넌트는 스택 비의존으로 작성됨([06]).

## 2.8 변경 이력 (v1 → v2)

사용성 검토(코치의 "훈련 종료 시 실력 향상 체크" 시나리오, 5회 이터레이션)를 거쳐 초기안을 다음과 같이 바꿨다.

| 항목 | v1 (초기안) | v2 (현재) | 이유 |
| --- | --- | --- | --- |
| 선수 배정 시점 | 출발 **전** 레인에 배정 | 출발 **후**(측정 종료) 배정 | 측정에 집중, 사전 세팅 부담 제거 |
| 측정 단위 | 익명 슬롯(도착 순서) | 동일 | — |
| 인원 설정 | 레인별 선수 지정 | **+/- 스테퍼**로 인원만 | 빠른 설정 |
| 추천 근거 | 출발 전 조합·활동 | **측정된 타임 ↔ 선수 이력 매칭** | 사후 배정에 자연스러움 |
| 선수 변경 시 | **타이머 리셋** | 비파괴적(데이터는 슬롯 키), 리셋은 *인원 수* 변경 시만 | 사후 배정이라 리셋 불필요 |
| 시간 표시 | 소수 1자리 | **소수 2자리(1/100초)** | 수영 규격 |
| 실력 향상 체크 | 기록지에서만 | 배정 화면에서 **이전→오늘·PB 즉시** | 코치의 핵심 효용 |
| 모호한 기록 | 미정의 | **"확인 필요" + 원탭 맞바꾸기** | 비슷한 타임의 오배정 방지 |
